# Независимые уведомления владельцу

В рабочей схеме 2 уровня контроля. На основном узле psy-alerts проверяет службы, очередь, память, сертификат и движение долгих задач. На отдельном существующем узле тот же модуль проверяет публичный HTTPS адрес снаружи. Оба пути отправляют только личное уведомление положительному Telegram ID владельца. В группу сообщения мониторинга не отправляются.

Работающий внешний наблюдатель не переносится на основной сервер: при потере основной машины уведомление должно прийти с другого узла. Для этого второму узлу нужен отдельно разрешенный доступ к учетным данным Telegram. Не публикуйте его конфигурацию.

## Подготовить внешний узел

Установите проверенные исходники и Python 3.12. На втором узле выполните:

```sh
sudo bash ops/install-observer
```

Установщик копирует psy_alerts.py и unit-файлы, создает закрытый шаблон. Он не включает таймер и не отправляет сообщения. В /etc/psy-observer/instance.env заполните положительный ID владельца и актуальный PSY_PUBLIC_URL. Затем сохраните прежний токен бота через скрытый ввод:

```sh
sudo python3 ops/stage-observer.py
```

Конфигурация принадлежит root и имеет права 600. Скрипт не создает нового Telegram-бота и не продлевает Codex. Для внешней проверки ключи OAuth не нужны.

До первого включения выполните read-only проверку в окружении службы:

```sh
sudo bash -c 'set -a; . /etc/psy-observer/instance.env; set +a; python3 -I /usr/local/libexec/psy-alerts.py --remote --check-only'
sudo systemctl enable --now psy-alerts.timer
```

При разрешенной проверке личных уведомлений используйте --test-notice вместо --check-only. Это отправляет сообщение только владельцу. Для проверки работы агента в группе уведомление мониторинга не подходит.

## После смены адреса

Одновременно обновите PSY_PUBLIC_URL на основном и внешнем узлах. В действующем старом экземпляре также может быть PSY_UPLOAD_URL, его значение должно совпадать. Перезапустите только oneshot-проверку, чтобы не принять уже идущий старый запрос за результат новой настройки. Проверьте /healthz с внешней машины и дождитесь следующего срабатывания таймера.

При постоянном отказе HTTPS внешний наблюдатель уведомляет владельца после 3 последовательных проверок. Это свидетельство доступности мини-апки. Оно не подтверждает ответ модели, целостность архива или появление TXT на телефоне участника. Эти проверки выполняются отдельно.

Монитор долгих задач проверяет продвижение этапов и сохраненных глав, а не ограничивает общую длительность лекции. Keepalive и служебные комментарии модели не считаются содержательным прогрессом. После сбоя выполняется повтор с сохраненным состоянием. При необходимости нового входа уведомление и кнопка авторизации отправляются владельцу в личку.
