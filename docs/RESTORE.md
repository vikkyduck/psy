# Восстановление PSY на новом сервере

Этот комплект рассчитан на Ubuntu 24.04 x86-64 с systemd, Python 3.12, ffmpeg и файловой системой с POSIX ACL. Для подключения нужны доступ администратора сервера, администратора Telegram-группы и владельца бота. Публичные исходники позволяют восстановить программы на пустой машине. Чтобы вернуть прежние диалоги или расшифровки, нужна отдельная закрытая резервная копия соответствующих данных.

## Подготовить машину

1. Клонируйте репозиторий в читаемый всеми сервисными пользователями каталог, например `/opt/psy-source`. Команды ниже предполагают этот путь. Защитите его от записи сервисными пользователями. Сохраните SHA выбранного релиза.
2. Установите `git`, `curl`, системный набор сертификатов, `acl`, `ffmpeg`, `poppler-utils`, `libseccomp2` и `python3-venv`. Выполните `sudo bash ops/prepare-host` из корня репозитория. Скрипт создает системных пользователей, приватные каталоги и права доступа.
3. Заполните `/etc/psy/instance.env` по образцу из `ops/`. Потребуются числовые ID владельца, супергруппы и бота, имя бота без @ и внешний HTTPS-адрес загрузчика. Сохраните права, выставленные установщиком. Токен Telegram и OAuth хранятся отдельно. Подробная инструкция для служб находится в [ops/README.md](../ops/README.md).

## Собрать шлюз и распознаватель

Выполните установку Hermes под пользователем `hermes`. Скачайте официальный установщик по URL, содержащему полный коммит, и передайте тот же коммит опцией `--commit`. Вызов фиксирует как сам установщик, так и checkout. На этом этапе можно пропустить необязательные браузерные компоненты.

```sh
sudo -u hermes -H bash <<'INSTALL'
set -eu
cd /home/hermes
ref=71d34bad1045610252eda02ee79549436896e784
script=$(mktemp)
trap 'rm -f "$script"' EXIT
curl -fsSL "https://raw.githubusercontent.com/NousResearch/hermes-agent/$ref/scripts/install.sh" -o "$script"
bash "$script" --commit "$ref" --hermes-home /home/hermes/.hermes --dir /home/hermes/.hermes/hermes-agent --non-interactive --skip-browser --skip-computer-use
INSTALL
sudo -u hermes -H python3 gateway/apply.py apply /home/hermes/.hermes/hermes-agent
sudo -u hermes -H python3 gateway/apply.py verify /home/hermes/.hermes/hermes-agent
```

Установите зависимости Telegram и локального STT в окружении Hermes по [инструкции установки окружения](../ops/README.md). Затем установите 2 отдельные среды Python для сервиса загрузки и службы распознавания. Скачайте зафиксированную модель Whisper и проверьте все 4 контрольные суммы. [Команды для сред и модели](../media/README.md)

Для нового экземпляра выполните `sudo bash ops/install-runtime --new-profile`. Скрипт устанавливает файлы мини-апки, профиль общения, навык транскрибации, модули проверки и unit-файлы systemd. Выполните `sudo bash ops/test-host`, пока службы еще выключены. Тест проверяет права на искусственных данных.

## Настроить подписку, Telegram и HTTPS

1. Под пользователем `hermes` выполните `/home/hermes/.hermes/hermes-agent/.hermes/bin/hermes auth add openai-codex --type oauth`. Войдите через ссылку и одноразовый код для собственного ChatGPT-аккаунта. После входа `hermes auth list` должен показывать `openai-codex`. Для нового профиля используйте одну основную подписку.
2. Добавьте токен собственного бота скрытым вводом и запустите `gateway/configure_profile.py` в окружении Hermes по инструкции шлюза. Выполните `sudo bash ops/stage-credential`. Это создает закрытый файл для systemd LoadCredential. Не вводите токены параметрами командной строки. [Настройка профиля](../gateway/README.md)
3. Обеспечьте доступ к `PSY_PUBLIC_URL` из Telegram. Адрес должен иметь действующий TLS-сертификат. Внешний порт должен совпадать с портом в URL или корректно проксироваться. Для штатного обработчика сертификатов используется имя `psy-upload` в Certbot. [Настройка TLS и запуска](../ops/README.md)
4. В BotFather для вашего бота настройте Main Mini App с URL загрузчика. Добавьте бота в указанную супергруппу. Для работы со всеми обращениями и закрепления кнопки ему нужны статус администратора и право закреплять сообщения. Владелец должен открыть личный чат с ботом.

Если восстанавливаете **тот же Telegram-бот на другом сервере**, подготовьте все до переключения. В согласованный момент завершите активные задания на старом сервере и остановите старый шлюз до запуска нового. У Telegram должен быть один потребитель обновлений. При проверке в отдельной группе используйте отдельного тестового бота.

Запустите `sudo bash ops/verify-ready`, затем включите службы и таймеры в порядке из инструкции ops. Проверьте в браузере `https://<ваш-хост>:<порт>/healthz`. Мини-апка открывается по основному URL в Telegram.

## Установить кнопку в Telegram

Сначала проверьте меню и закреп. Команда ниже использует уже подготовленные файлы конфигурации и учетные данные на новом сервере. В журнал и историю команд попадут только имена переменных и пути.

```sh
sudo bash -c 'set -a; . /etc/psy/instance.env; set +a; export CREDENTIALS_DIRECTORY=/etc/psy-upload; python3 /opt/psy-source/tools/telegram_entry.py check'
```

Чтобы создать кнопку "Записи" в личном меню владельца и закрепить сообщение с кнопкой в группе, замените `check` на `install`. Режим установки публикует сообщение в настроенной группе только при необходимости. Если связь оборвалась во время отправки, проверьте, появилось ли сообщение, прежде чем пытаться опубликовать его повторно. Режим `check` ничего не отправляет в чаты.

## Принять восстановленный экземпляр

- Проверьте `systemctl is-active hermes-gateway psy-upload psy-upload-worker psy-asr` и `systemctl is-enabled` для этих же служб. Для диагностики используйте `journalctl -u hermes-gateway` на сервере.
- Отправьте короткий вопрос в разрешенную группу. Уточните его вторым сообщением и убедитесь, что ответ пришел в ту же тему. Проверьте личный доступ владельца и отказ для постороннего аккаунта.
- Из закрепа откройте "Записи", загрузите искусственный файл больше 20 МБ. Убедитесь, что TXT вернулся в исходную группу и его текст соответствует записи. Проверьте, что другой участник не видит эту загрузку в своей истории.
- Если нужен перенос исторических данных, восстановите их из частной резервной копии в обслуживаемое окно. После восстановления проверьте владельцев, ACL и незавершенные отправки. Статус неопределенной доставки требует ручной проверки в Telegram во избежание дубликата.

Если переносите очередь групповых заданий, сохраните SQLite-базу группы и ее привязку к боту и чату. На новой машине сверяйте оба идентификатора до первого запуска. Восстановленная очередь приостановленных лекций содержит готовые главы и сроки повторов отправки.

При переносе авторизации сохраните в одном закрытом резервном наборе состояние входа и журнал уже начатых обменов Codex. Восстановление старой копии после ротации ключа может потребовать нового входа владельца. Проверьте работоспособность обычным модельным запросом и штатным запуском таймера. Для сверки PDF установите системный пакет poppler-utils.
