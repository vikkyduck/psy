# Восстановление PSY на новом сервере

Инструкция сверена с исходниками и односерверной установкой 14 ноября 2026 года. Рабочая схема: один основной сервер с Hermes, Mini App, офлайн-распознавателем и отправкой результатов. Отдельный существующий узел хранит зашифрованные копии и проверяет доступность основного. Постоянный промежуточный сервер для прежнего IP не требуется.

Есть 2 варианта восстановления. Для нового бота используйте пустой профиль и новый вход. Для прежнего бота сначала верните закрытые данные, ключи подписанных загрузок и состояние OAuth из актуальной копии. Новый вход и новый ключ подписания поверх восстановленных данных создавать не следует.

## Подготовить свободную машину

Команды рассчитаны на Ubuntu 24.04 x86-64, systemd, ядро 6.8+ и POSIX ACL. В рабочей установке используется 2 ГБ RAM, 1 CPU и 50 ГБ диска. Это параметры проверенного узла, а не гарантия достаточности для любой нагрузки. Шлюз работает от hermes, остальные компоненты имеют отдельные системные учетные записи.

1. Получите проверенный релиз этого репозитория в `/opt/psy-source`. Каталог принадлежит администратору и недоступен сервисам на запись. Сохраните SHA релиза.
2. Установите зависимости и подготовьте учетные записи. Скрипты подготовки не запускают службы.

```sh
sudo apt-get update
sudo apt-get install -y acl ca-certificates curl ffmpeg git gnupg libgomp1 libseccomp2 openssh-client poppler-utils python3-venv rsync util-linux zstd
cd /opt/psy-source
sudo bash ops/prepare-host
```

Не выполняйте установку поверх работающего экземпляра. Если прежний сервер доступен, финальная синхронизация данных проводится после завершения активных заданий и остановки старого шлюза, работников и таймеров авторизации. У Telegram должен быть один потребитель обновлений, у Codex - один владелец текущего состояния входа.

## Установить программы без запуска бота

Версия Hermes закреплена на официальном коммите `71d34bad1045610252eda02ee79549436896e784`. URL установщика и аргумент установки указывают один и тот же коммит. Факультативные браузерные компоненты можно пропустить.

```sh
sudo -u hermes -H bash <<'INSTALL'
set -eu
cd /home/hermes
ref=71d34bad1045610252eda02ee79549436896e784
script=$(mktemp)
trap 'rm -f "$script"' EXIT
curl -fsSL "https://raw.githubusercontent.com/NousResearch/hermes-agent/$ref/scripts/install.sh" -o "$script"
bash "$script" --commit "$ref" --hermes-home /home/hermes/.hermes --dir /home/hermes/.hermes/hermes-agent --non-interactive --skip-browser --skip-computer-use
INSTALL
sudo -u hermes -H python3 gateway/apply.py apply /home/hermes/.hermes/hermes-agent
sudo -u hermes -H python3 gateway/apply.py verify /home/hermes/.hermes/hermes-agent
```

Установите зависимости Hermes, 2 среды Python загрузчика и распознавателя и проверенную модель Whisper по [ops/README.md](../ops/README.md) и [media/README.md](../media/README.md). Контрольные суммы 4 файлов модели находятся в `media/model.sha256`.

Для прежнего бота установите runtime без перезаписи профиля:

```sh
sudo bash ops/install-runtime
```

Для нового бота с пустым хранилищем используйте `sudo bash ops/install-runtime --new-profile`. Не используйте этот флаг для замены восстановленного личного SOUL.md. `install-runtime` сам определяет новый Linux UID hermes для зависимости `user@UID.service`. Переносить числовой UID старой машины в unit-файл нельзя.

## Вернуть закрытые данные прежнего бота

Для этой ветки выполните [docs/RECOVERY.md](RECOVERY.md) до авторизации и до первого старта. Публичный GitHub хранит программы и шаблоны. Диалоги, документы, главы, аудио, OAuth и ключи подписания восстанавливаются из отдельного зашифрованного набора.

Критические правила:

- Состояние OAuth, credential pool, журналы незавершенного обмена и восстановления записи возвращаются вместе. Поздняя копия с новым ключом имеет приоритет над ранней.
- Восстанавливается исходный `recording-signing`. Без него существующие билеты, задания, сеансы и квитанции перестанут проходить проверку.
- Очередь загрузки и база результатов работника восстанавливаются совместно с медиа. SQLite берется из каталогов согласованных снимков `db/` и `sysdb/`, а не из случайно скопированного живого файла.
- Возвращаются владельцы и ACL по именам учетных записей. Режим 600 для OAuth и токенов сохраняется. Числовые UID новой машины могут отличаться.
- Готовые главы и сегменты расшифровки сохраняются вместе с их состоянием. Перед повторной отправкой записи с неопределенным результатом нужна проверка факта доставки.

Для восстановленного действующего OAuth новый device-code не требуется, пока проверка не покажет необходимость повторного входа. Для восстановленного токена скрытый ввод пропускается. `ops/stage-credential` извлекает существующий токен в root-only credential без вывода значения.

## Настроить экземпляр, Codex и HTTPS

Заполните `/etc/psy/instance.env` по образцу `ops/instance.env.example`. Потребуются ID владельца, группы и бота, имя бота и один актуальный публичный HTTPS origin Mini App. В этом файле нет токена или OAuth. Публичные модули получают адрес из `PSY_PUBLIC_URL`. При восстановлении старой конфигурации с `PSY_UPLOAD_URL` приведите его к тому же значению. Не оставляйте разные адреса у загрузчика, шлюза и мониторинга.

Для нового экземпляра добавьте токен через скрытый ввод и настройте профиль по [gateway/README.md](../gateway/README.md). Для прежнего проверьте восстановленные ID и профиль, не подменяя их демонстрационными значениями. Службы читают конфигурацию через EnvironmentFile, включая сокетные брокеры и проверку загрузчика.

```sh
sudo bash ops/stage-credential
```

Для нового входа используйте только `openai-codex` через ChatGPT OAuth/device-code. Команды выполняются от hermes с HERMES_HOME=/home/hermes/.hermes. Проверка: `hermes auth list`, `model.provider=openai-codex` и короткий one-shot. Не добавляйте OPENAI_API_KEY, OpenRouter или альтернативного провайдера при ошибке.

Настройте прямой доступ к новому серверу: TCP 80 для ACME и порт Mini App, по умолчанию 9443. Получите сертификат для адреса из `PSY_PUBLIC_URL`. Полные команды для DNS и IP есть в [ops/README.md](../ops/README.md). Рабочее имя линии Certbot после переноса - `psy-upload-ip`. Оно согласовано с deploy hook и таймером в этом репозитории. Если закрытая копия содержит другую линию, согласуйте все 3 места до старта.

```sh
sudo /usr/local/libexec/psy-upload-deploy-cert --stage
sudo bash ops/verify-ready
```

Не переносите старые Node/Python окружения как обязательный способ установки. Их собирают из зафиксированных зависимостей. Не восстанавливайте архив целиком поверх /etc и новых unit-файлов.

## Сохранить знакомую кнопку "Записи"

При прежнем имени бота групповая кнопка использует ссылку `https://t.me/<имя_бота>?startapp=psy_group`. Ее можно оставить в прежнем закрепе при смене сервера.

1. В BotFather обновите Main Mini App URL на новый HTTPS origin.
2. Обновите глобальное меню бота и индивидуальное меню владельца. Telegram допускает индивидуальную настройку, которая имеет приоритет над общей.
3. Оставьте неизменным существующий групповой закреп, если он указывает на тот же startapp. Не создавайте второй закреп только из-за смены IP.
4. Измените адрес внешнего наблюдателя на втором узле.

Без отправки в чаты можно выполнить:

```sh
sudo bash -c 'set -a; . /etc/psy/instance.env; set +a; export CREDENTIALS_DIRECTORY=/etc/psy-upload; python3 /opt/psy-source/tools/telegram_entry.py check'
```

`check` ничего не публикует. `install` меняет меню и при необходимости публикует/закрепляет сообщение в группе. Используйте `install` только при разрешенной публикации. При восстановлении существующей кнопки сначала проверяйте и обновляйте меню, не отправляя новое сообщение.

## Включить и принять восстановленный экземпляр

Запускайте сокеты, ASR, загрузчик и работника, затем шлюз. После `connected` включайте таймеры. Порядок и команды находятся в [ops/README.md](../ops/README.md).

Проверьте:

- `hermes --version`, `hermes auth list`, провайдера и короткий реальный one-shot через подписку.
- `systemctl is-active` и `systemctl is-enabled` для hermes-gateway, psy-upload, psy-upload-worker, psy-asr.
- HTTPS `/healthz` с внешнего узла. Без авторизации `/api/jobs` должен возвращать 401.
- Настоящую кнопку в Telegram и файл больше 20 МБ. Проверяйте полный файл, контрольную сумму, распознавание и появление TXT в выбранном чате.
- Если в группу писать запрещено, проводите настоящий тест в личке владельца и отдельно изолированную проверку группового маршрута. Такой тест не подтверждает появление TXT на телефоне участника группы.
- Прежнюю запись и документы из закрытой копии, SQLite integrity_check и права доступа.
- Сухой прогон продления сертификата уже только для нового адреса, независимый мониторинг и получение зашифрованной копии на внешнем узле.

Только после этих проверок завершайте использование старого узла. Дождитесь окончания открытых загрузок, проверьте отсутствие зависимостей от старого адреса, сохраните свежую копию. Если цель - прекратить оплату старой машины, ее удаляют после приемки, а не просто выключают. Восстановление входа из устаревшего состояния и одновременный старт двух шлюзов недопустимы.

Автоматический перезапуск и сохранение этапов не доказывают отсутствие потерь при любой аварии. Гарантии RPO=0 и полного восстановления за 5 минут эта инструкция не заявляет.
