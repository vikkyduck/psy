# Проверка ПСИ без сообщений в рабочую группу

Проверки используют текущие программные модули, отдельные базы и синтетические данные. Переписка, исходные записи участников и действующий Telegram-токен в тестовые наборы не копируются.

| Проверка | Что настоящее | Что тестовое |
|---|---|---|
| 40 проверок надежности | Исправленные функции завершения, монитора и установщика | Время ожидания, состояния службы, отправитель и аварийные задачи |
| Ответ участнику | Групповой обработчик, очередь, хранилище, PTB и действующий Codex | Участник, группа, Telegram credential и локальный Bot API |
| Большая запись | Код кнопки, HTTP загрузка, подписи, ASR-протокол, Whisper, квитанции и отправка TXT | DOM, WebApp initData, участник, ключи и локальный Bot API |

Граница изолированной доставки находится у локального приемника. Результат не подтверждает появление сообщения на телефоне настоящего участника. В примере большого файла используется короткая искусственная речь, поэтому он не измеряет пропускную способность для многочасовых записей.

## Проверки надежности

Сначала восстановите проверенный checkout официального Hermes и примените текущий `gateway/apply.py` по [RESTORE.md](RESTORE.md). `PSY_TEST_GATEWAY` указывает именно на эту восстановленную копию, а не на рабочую папку с независимыми изменениями.

```sh
PSY_TEST_GATEWAY=/var/tmp/psy-clean-hermes python3 -m unittest discover -s tests/reliability -p 'test_*_release.py' -v
```

Ожидается 40 успешных проверок. 7 из них проверяют сохраненную тестовую транзакцию установки от 24 ноября в `tests/reliability/cas_fixture.py`. У нее нет рабочего CLI или путей сервера. Общий инструмент последующих обновлений остается `ops/update_live.py`, его отдельные тесты находятся в `ops/tests`. Этот набор не обращается к модели или настоящему Telegram. Он воспроизводит:

- Задачу, которая продолжает ждать после отмены.
- Зависшие executor, control-server и функцию выхода.
- Исключение после сохранения состояния.
- Сохранение 3 глав дольше уменьшенного тестового бюджета финального выхода без потери их содержимого.
- Ошибку сохранения и внешнюю отмену, которые не должны выдавать безопасную точку за уже достигнутую.
- Нормальный 70-секундный перезапуск без ложной тревоги, затянувшийся переход и настоящий отказ.
- Восстановление при заполненных 4 часовых слотах, реальный `retry_after` и отсутствие дубля.
- Отказ установки при независимом изменении исходника и защиту от опасного отката поверх нового изменения.

## Подготовить отдельные серверные примеры

Примеры находятся в [tests/isolated](../tests/isolated). Для них нужны установленный текущий ПСИ и права администратора только на создание тестовых каталогов и отдельного сетевого пространства. Рабочие службы не останавливаются.

Пути ниже соответствуют стандартной установке: репозиторий `/opt/psy-source`, checkout `/home/hermes/.hermes/hermes-agent`, среда загрузчика `/opt/psy-upload-venv`, среда ASR `/opt/psy-asr-venv`, модель `/opt/psy-asr-model`. Если восстановленный экземпляр настроен иначе, используйте предусмотренные аргументы скриптов. Действующие адреса, ID и учетные данные в команды не подставляются.

Установленные Node.js должны поддерживать `File`, `fetch` и WebCrypto. Проверенный серверный прогон использовал Node.js 24.22.3. Для изолированного примера загрузки нужны `unshare` и `ip`, а для генерации речи - уже установленные `ffmpeg` и Mac `say` или Linux `espeak-ng`. Сценарии сами ничего не устанавливают.

## Использовать выбранную среду Hermes

Не предполагайте наличие `.hermes/bin/python` или прежнего `.venv/bin/python`. Launcher и настоящий интерпретатор могут находиться в разных каталогах.

Сценарий [run_on_host.py](../tests/isolated/run_on_host.py) читает уже выбранную пакетную среду через `committed_venv()`, находит настоящий интерпретатор и запускает только публичный тестовый код в отдельном каталоге. Сам групповой пример подключает библиотеки через `site_packages()` без выполнения `.pth`. Сценарий не вызывает подготовку обновления, установку пакетов или переключение окружения.

Если выбранной среды нет, сначала завершите восстановление зависимостей по [ops/README.md](../ops/README.md). Не вызывайте полный `hermes_bootstrap` только ради импорта `telegram`: он способен выполнять служебное восстановление обновления.

## Проверить ответ участнику

Для предварительной проверки соединения компонентов есть явный режим подмены модели:

```sh
sudo python3 /opt/psy-source/tests/isolated/run_on_host.py group --stub-model
```

Его результат содержит `real_codex=false` и не является проверкой подписки. Настоящий модельный пример запускается без этого флага:

```sh
sudo python3 /opt/psy-source/tests/isolated/run_on_host.py group
```

Используется единый действующий контроллер Codex OAuth. Его состояние не копируется в отдельный профиль и не получает второго владельца продления. Telegram credential и идентификаторы в тесте вымышленные. Если действующий вход недоступен, пример сообщает безопасную категорию ошибки и не заменяет модель заглушкой или другим провайдером.

Ожидаемые признаки успеха:

- `status=passed`, `real_codex=true`, `provider=openai-codex`.
- На вопрос про 17 плюс 25 получен ответ `42`.
- `codex_http_requests` не меньше 1, `group_model_invocations=1`.
- `captured_group_answers=1`, `duplicate_update_extra_answers=0`.
- История и ID исходящего ответа связаны с тестовым участником во временной БД, история другого участника пуста.
- `real_telegram_requests=0`, `guard_denials=0`.

TCP и HTTP разрешены только конкретному loopback-приемнику и официальным адресам OpenAI. Доступ к рабочим бизнес-базам и каталогам материалов запрещен. Служебные запросы версии Git ограничены чтением точных метаданных без транспорта и вспомогательных программ. Запрос статуса дерева не запускает Git.

Тестовый срок ожидания относится к контрольному примеру. Он не меняет длительность лекций и глубоких разборов ПСИ. Реальный модельный прогон не выполняют в публичном CI с действующими учетными данными.

## Проверить обычные задачи и память диалога

Стенд [quality_compare.py](../tests/isolated/quality_compare.py) сравнивает старые и новые групповые модули на фиксированных синтетических входах. Полные правила изоляции, повторных попыток и восстановления находятся в [QUALITY.md](../tests/isolated/QUALITY.md). Этот раздел задает процедуру приемки, результаты конкретного выпуска фиксируются отдельно.

| Сценарий | Что проверять в ответе |
|---|---|
| `ordinary_multipart` | Все расчеты учебной задачи, формулы, допущение, функция Python, два проверочных `assert` и обязательное последнее предложение |
| `project_plan` | План на четыре недели, расчет нагрузки двух исполнителей, зависимости, охват всех статей, четыре риска с действиями, критерии приемки и готовое сообщение команде |
| `memory_update8` | Новые бюджет, срок, роли и колонки итоговой таблицы после восьми последующих обменов, без возврата отмененных значений |
| `memory_cancel_topic` | Отмена ограничений закрытого проекта и переход к объяснению другой темы без старого бюджета, команды, срока и табличного формата |
| `memory_compacted` | Сохранение действующих требований после реального сжатия старой части истории при отдельном тестовом бюджете 4096 токенов |

Для обоих вариантов используйте одну действующую модель, один настоящий интерпретатор Hermes, одинаковую версию стенда и одинаковые условия доступа к источникам. Сохраняйте хеши выбранных модулей. Названия `baseline` и `candidate` служат только ключами соответствия, сами по себе они не подтверждают происхождение исходников. Входы `case_turns()` содержат один и тот же текущий запрос и полную синтетическую историю. Предполагаемые правильные ответы и контрольные пункты из `review_checks` модели не передаются.

До запуска определите `psy_runtime_python` по [инструкции установки токенизатора](../ops/README.md#локальный-токенизатор-для-длинной-истории). Не подменяйте его Python загрузчика или распознавателя. Для кандидата требуется совместимый отдельный выпуск токенизатора и проверенный кеш `o200k_base`. Проверка под другим ABI не подтверждает работу в среде шлюза.

В примере ниже `psy_quality_harness` указывает на проверенный скрипт стенда, `psy_hermes_checkout` - на действующий Hermes с выбранными зависимостями, `psy_baseline_modules` и `psy_candidate_modules` - на подготовленные каталоги групповых модулей сравниваемых версий. `psy_quality_output` - заранее созданный приватный каталог режима 0700, принадлежащий `hermes`, вне рабочего профиля, checkout и исходников. Все значения являются абсолютными путями. Стенд не создает Telegram-транспорт и не изменяет рабочие службы.

```sh
for psy_case in ordinary_multipart project_plan memory_update8 memory_cancel_topic memory_compacted
do
  sudo -Hu hermes timeout --signal=TERM --kill-after=30s 120m \
    "$psy_runtime_python" "$psy_quality_harness" \
    --checkout "$psy_hermes_checkout" --module-dir "$psy_baseline_modules" \
    --case "$psy_case" --variant baseline --output-root "$psy_quality_output"
  sudo -Hu hermes timeout --signal=TERM --kill-after=30s 120m \
    "$psy_runtime_python" "$psy_quality_harness" \
    --checkout "$psy_hermes_checkout" --module-dir "$psy_candidate_modules" \
    --case "$psy_case" --variant candidate --output-root "$psy_quality_output"
done
```

Внешний срок ограничивает только приемочный процесс, включая ожидание повторной попытки. Завершение по этому сроку является незавершенным прогоном. Оно не меняет производственные параметры генерации. Для этих пяти заданий внешний поиск не нужен. Успех повторного запуска не стирает исходный сбой, оба результата и их условия сохраняются.

`memory_compacted` - отдельный стресс-тест. Кандидат получает тестовый бюджет входного контекста 4096 токенов, а старая версия, у которой нет такого интерфейса, получает тот же полный диалог без дополнительного параметра. Поэтому эту пару нельзя выдавать за сравнение при одинаковых настройках окна. В остальных четырех сценариях тестовое уменьшение окна не применяется. Для приемки сжатия проверяйте `tokenizer.available=true`, `tokenizer.estimator=o200k_base`, `quality_metadata.context_audit.token_estimator=o200k_base` и `quality_metadata.context_audit.compacted_messages > 0`. Оценка UTF-8 по байтам не считается выполнением условия о 4096 токенах.

Сначала передайте оценщику только перемешанные файлы `review/answer-*.txt`. В них есть исходная история, запрос и результат, но нет подписи версии. Зафиксируйте оценки отдельно по выполнению задания, точности, глубине, связности, языку и границам интерпретации. Глубина оценивается относительно задачи: короткий вопрос не требует длинного ответа. Придуманная цитата или атрибуция и частичный результат, представленный полным, блокируют приемку независимо от среднего балла.

После фиксации слепых оценок сверьте конкретные обязательства с файлами `grading/answer-*.json`, затем раскройте соответствия в `keys/answer-*.json`. Начальный `grading.status=not_reviewed` и технический `status=generated` не означают содержательной приемки. Приватная карта сжатой истории не публикуется в технических метаданных, там остаются только `context_audit` и сведения о токенизаторе. Реальные запросы Telegram и нарушения ограничений стенда должны отсутствовать.

Эта проверка запускает композицию с полной фиксированной историей и не воспроизводит старое ограничение выборки из базы на шесть обменов. Сохранность истории, порядок сообщений, изоляция участника, темы и источника, отмена правки, повторное использование карты и отсутствие приватного текста в техническом аудите проверяются отдельно наборами `gateway/tests/test_conversation_context.py`, `test_store_engine.py` и `test_source_context.py`. Изолированная композиция также не доказывает доставку реальному участнику или равенство всей системы приложению на Маке.

## Создать искусственный файл больше 20 МиБ

Генератор [generate_reference.py](../tests/isolated/generate_reference.py) использует только текст из [reference.txt](../tests/isolated/reference.txt). Запись участника и рабочая очередь ему не нужны. На Mac используется локальный `say`, на Linux - локальный `espeak-ng`, затем `ffmpeg`. В публичный репозиторий аудиофайл не записывается.

Создайте приватный каталог администратора и выполните генератор. Сценарий запуска затем скопирует искусственный WAV в свой временный каталог и передаст его непривилегированному работнику:

```sh
sudo install -d -m 0700 /var/tmp/psy-audio-fixture
sudo python3 /opt/psy-source/tests/isolated/generate_reference.py \
  --fixture-dir /var/tmp/psy-audio-fixture \
  --output /var/tmp/psy-audio-fixture/reference.wav
```

Генератор отказывается перезаписывать существующий файл. Для повторной проверки используйте новый приватный каталог. Результат - 40 секунд, 192 кГц, 2 канала, PCM16, около 30,72 МБ. Контрольная фраза содержит `green`, `train`, `London`, `nine` и число `47`.

Эта операция увеличивает размер файла частотой дискретизации и заполнением до 40 секунд. Для проверки долгих записей нужен отдельный нагрузочный пример.

## Проверить Mini App и доставку TXT

Сценарий запускает пример от существующего непривилегированного `psy-deliver`. Текущий ASR-сервер проверяет UID клиента через `SO_PEERCRED`, поэтому произвольный пользователь не подходит.

Весь прогон выполняется в отдельном network namespace с единственным интерфейсом `lo`. Сам сценарий проверяет это до импорта прикладных модулей и отказывается запускаться в обычной сети.

```sh
sudo python3 /opt/psy-source/tests/isolated/run_on_host.py upload \
  --fixture-dir /var/tmp/psy-audio-fixture \
  --source /var/tmp/psy-audio-fixture/reference.wav \
  --upload-python /opt/psy-upload-venv/bin/python \
  --asr-python /opt/psy-asr-venv/bin/python \
  --model /opt/psy-asr-model
```

Если расположение Python или модели отличается, задайте соответствующие аргументы. Для теста не меняют рабочие unit-файлы, сокеты, токены и конфигурацию. Сценарий передает чистое окружение, копирует только публичные модули и искусственный файл, после завершения удаляет свой временный каталог. `group_example.py` и `upload_example.py` используют одинаковую синтетическую группу.

Ожидаемые признаки успеха:

- Синтетический участник отличается от владельца, после авторизации назначение равно группе.
- `ui_send_taps=1`, `actual_dom_handler=true`, `progress_percent=100`.
- `recovered_lost_chunk_reply=true`, размер больше 20 МиБ, SHA-256 совпадает.
- `asr_mode=real_socket_service_and_installed_whisper`, все контрольные слова найдены.
- `fake_group_documents_received=1`, обе квитанции имеют `sent` и одинаковый ID сообщения.
- `duplicate_documents=0`, `denied_nonmember=true`.
- `persisted_receipt_acknowledged=true`: после сохранения результата служба удалила приватную папку ASR-задания.
- `fixture_state_only=true`, `external_network_blocked=true`, `production_telegram_calls=0`.

В этом примере действуют текущий `send.onclick`, авторизация с подписанным групповым initData, HTTP-обработчики, настоящий ASR-клиент и отдельный экземпляр ASR-службы. Проверяются приватный снимок, digest, Whisper, сохранение квитанции и подтверждение через Unix-протокол. Подменены DOM/WebApp, членство синтетических пользователей и внешний Telegram. Рабочий ASR-сокет не используется.

## Проверить рабочий экземпляр после тестов

Сверьте исходные SHA-256 программ с манифестом. Проверьте отсутствие синтетических ID сценариев в рабочих очередях, истории и базе квитанций. Используйте счетчики, а не публикацию содержимого баз.

Проверьте `active` для шлюза, загрузчика, работника и ASR, `enabled` для автозапуска, совпадение PID control socket с текущим процессом и Telegram `connected`. Изолированные примеры не требуют перезапуска рабочего шлюза.

В публичные результаты включайте только обезличенные счетчики, контрольные суммы и вымышленный текст. Реальные ID участников, PID, внутренние IP, абсолютные пути профиля, секреты, полные binding с подписью и содержимое рабочего запроса в них не входят. После проверки удалите временные искусственные файлы из отдельных каталогов.
