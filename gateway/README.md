# Восстановление шлюза PSY

Основа шлюза - официальный коммит Hermes `71d34bad1045610252eda02ee79549436896e784`. Сценарий ожидает каталог Git с этим HEAD и HTTPS origin NousResearch. Нужен Python 3.9 или новее для установки патча. Для работы Hermes используйте версию Python и изолированную среду из официального установщика этой ревизии. [Исходный коммит](https://github.com/NousResearch/hermes-agent/commit/71d34bad1045610252eda02ee79549436896e784)

Сообщения разрешенной группы передаются штатному Hermes без изменения текста, вложений и цепочки ответов. До этого проверяются одновременно ID группы и отправителя. В закрытом файле профиля `.env` задайте `TELEGRAM_GROUP_ALLOWED_USERS` как список разрешенных числовых ID через запятую. Пустой список и `*` отклоняются. Вход остается через `openai-codex`, сжатие контекста включено на 50%, существующий `privacy.conf` сохраняется. Отдельная групповая очередь и генератор ответов при запуске шлюза больше не включаются.

Исторические модули и `vault/group-psy/group.sqlite3` сохранены для чтения прежних материалов и диагностики. `tools/migrate_group_history.py` переносит исходные пары сообщений в уже существующую штатную сессию. Сначала требуются согласованные копии SQLite и пробный перенос на копии. Скрипт проверяет целостность, неизменность старых сообщений и повторный запуск без дублей. Время импортированных строк обозначает время переноса, поскольку старая таблица не содержала дат сообщений.

На остановленном целевом узле в каталоге этого репозитория выполните следующие команды от владельца checkout. Переменная `CHECKOUT` указывает на каталог установленного Hermes.

```sh
python3 gateway/apply.py apply "$CHECKOUT"
python3 gateway/apply.py verify "$CHECKOUT"
PYTHONDONTWRITEBYTECODE=1 python3 gateway/test_gateway.py "$CHECKOUT"
```

Патч изменяет 9 отслеживаемых файлов Hermes. Установщик добавляет 23 файла: модули группы, ее запросов к модели и передачи записей в каталоге адаптера Telegram, модуль проверки параметров экземпляра, сценарий оператора `psy_group_admin.py`, общую политику обновления входа Codex для шлюза и таймера и мост `hermes_cli/psy_platform_bridge.py`, через который соседняя платформа пользуется тем же входом Codex и уведомлениями владельцу. Общий исходник для `psy_upload_handoff.py` хранится в `media/telegram_handoff.py`. После установки `manifest.json` позволяет проверить SHA-256 каждого из 32 файлов. `group-manifest.json` содержит те же 32 контрольные суммы для проверки границы доступа перед запуском службы. Оба манифеста также содержат сумму общего модуля `/usr/local/lib/psy-common/psy_common.py` (исходник `common/psy_common.py`): его ставит root вне папки Hermes, а шлюз загружает по явному пути вместе с модулем загрузки записей. Независимые изменения в целевых файлах прерывают установку. Повторный запуск завершает прерванную установку.

Состав релиза задают только списки `TRACKED`, `ADDED` и `SHARED` в `apply.py`. После изменения патча, модуля или `common/psy_common.py` пересчитайте оба манифеста командой `python3 gateway/apply.py release "$CHECKOUT"`. Тесты шлюза сверяют манифесты, список проверки `ops/libexec/preflight.py` и числа в этом разделе с этими списками.

Для запуска тестов нужен Python 3.11 или новее. Для проверки тесты используют искусственные идентификаторы, временные базы SQLite и имитацию ответов Codex. Проверяются разрешенные чаты, изоляция участников и тем, загрузка записи, восстановление очереди, обработка исчерпанных квот, выбор OAuth и мост платформы через локальный Unix-сокет. Тесты не вызывают внешние API.

## Архив заданий прежнего обработчика

Старая очередь больше не принимает и не исполняет новые запросы. Ее состояние доступно оператору от пользователя hermes:

```sh
sudo -u hermes python3 -I "$CHECKOUT/plugins/platforms/telegram/psy_group_admin.py" list
```

Сценарий выводит только номера и служебные сведения, без текста сообщений. Незавершенные старые запросы нужно разобрать до переключения на штатный маршрут.

## Параметры профиля

В `ops/instance.env.example` указаны имена параметров. Установите на целевой машине `PSY_OWNER_ID`, `PSY_GROUP_ID`, `PSY_BOT_ID`, `PSY_BOT_USERNAME` без @ и `PSY_PUBLIC_URL` с HTTPS. Используйте один набор значений для шлюза, загрузчика и служб, выдающих доступ. Конфигурация PSY предназначена для одного бота. Несовпадение его ID при подключении блокирует обработку обновлений.

Сценарий `configure_profile.py` запускается от системного пользователя hermes после установки патча, с переменными экземпляра в окружении. Он использует Telegram-токен из закрытого файла профиля `.env` или из файла `telegram-token.pending` с правами 0600. Проверьте числовой префикс токена по `PSY_BOT_ID`. Привязку подписки выполните через штатный вход Codex по коду устройства. Если восстанавливается существующий пул, используйте актуальную закрытую копию профиля и последовательность переключения из инструкции. [Восстановление узла](../docs/RESTORE.md)

Профиль включает Codex OAuth, режим генерации изображений, локальное распознавание, закрытые личные сообщения, доступ в одну группу, уведомления Telegram и хранение результатов. При настройке с нуля выбирается модель `gpt-6.1-sol`. Для уже настроенного провайдера `openai-codex` сохраняется его модель. Совместимость модели и доступность подписки проверяются после входа. Публичный профиль составлен по конфигураторам и проверкам проекта.

Исходники патча Hermes распространяются на условиях MIT. [Лицензия исходной версии](LICENSE.upstream)
