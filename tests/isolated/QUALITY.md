# Изолированное сравнение качества

`quality_compare.py` вызывает реальный Codex через выбранные модули группового
конвейера. Входы зафиксированы в коде и полностью синтетические. Для каждого
варианта нужен отдельный процесс. Отправки в Telegram отсутствуют.

Запуск выполняется от `hermes` установленным интерпретатором Hermes. Переменные
в примере обозначают уже выбранные оператором абсолютные пути. `HERMES_CHECKOUT`
содержит рабочий runtime и существующую общую OAuth-авторизацию. `CANDIDATE_MODULES`
содержит кандидатные модули. `QUALITY_OUTPUT` - заранее созданный каталог с правами
0700, принадлежащий `hermes`, вне runtime, рабочей конфигурации и репозитория.
Секреты не копируются. Модель и рабочие ограничения генерации не меняются.

```sh
timeout --signal=TERM --kill-after=30s 120m "$HERMES_PYTHON" "$QUALITY_HARNESS" \
  --checkout "$HERMES_CHECKOUT" \
  --case lecture180_local --variant baseline --output-root "$QUALITY_OUTPUT"

timeout --signal=TERM --kill-after=30s 120m "$HERMES_PYTHON" "$QUALITY_HARNESS" \
  --checkout "$HERMES_CHECKOUT" --module-dir "$CANDIDATE_MODULES" \
  --case lecture180_local --variant candidate --output-root "$QUALITY_OUTPUT"
```

Для первого запуска подходит `--case short`. Другие сценарии: `concepts`,
`comparison`, `closed_link`, `lecture30_local`, `lecture180_sources`.

## Повторные попытки и восстановление

По умолчанию один запуск допускает три попытки композиции. `--max-attempts`
принимает 1, 2 или 3. Повторяются только ошибки, которые сама выбранная версия
`ModelIssue` помечает `retryable`. Стенд вызывает производственные
`wait_for_model`, `next_retry_delay` и `claim_next`. Задержки не сокращаются,
`EFFORT_MARK` и глубина рассуждения не меняются стендом. Внешний `timeout`
ограничивает суммарное время, включая ожидание. Одна длинная квотная пауза может
исчерпать этот срок раньше следующей попытки.

После каждого `ModelIssue` стенд сохраняет атомарный SQLite backup и manifest в
`recovery/answer-<код>-attempt-<номер>/` до ожидания или завершения процесса.
Снимки сохраняют реальные промежуточные стадии и реальную отметку переключения
глубины. Они содержат синтетические тексты и не предназначены для публичной
публикации или слепого оценщика. При жестком завершении процесса во время API-вызова
нового снимка может не быть, используется последний уже сохраненный снимок.

Для продолжения добавить:

```sh
--resume-state "$QUALITY_OUTPUT/recovery/имя-снимка"
```

Это должен быть непосредственный приватный подкаталог `output-root/recovery`
с двумя файлами `group.sqlite3` и `manifest.json`, права файлов 0600, каталога 0700,
владелец - пользователь запуска. SQLite должен быть создан через backup API,
без WAL и SHM рядом. Копирование главного файла работающей WAL-базы недостаточно.
До запуска модели байты копируются в новый fixture. SQLite открывается только
внутри этого fixture. Проверяются целостность, схема, синтетические участник и
задание, отсутствие истории, документов, доставки, посторонних таблиц и триггеров.

Manifest должен совпадать с выбранными case, variant, текстом входа и хешами всех
`psy_*.py`. Если модель указана, она должна совпадать с действующей конфигурацией.
Для упаковки уже сохраненного оператором атомарного backup доступен чистый helper:

```python
manifest = quality_compare.recovery_manifest(
    "concepts", "candidate", Path("/selected/plugins/platforms/telegram"),
    model=None,
    historical_attempts=[{"label": "старый-код", "status": "failed", "kind": "timeout"}],
)
quality_compare.write_private(
    snapshot / "manifest.json",
    json.dumps(manifest, ensure_ascii=False, indent=2) + "\n",
)
```

Helper не читает базу, конфигурацию или авторизацию. `input_sha256` считается от
UTF-8 JSON результата `case_turns(CASES[case])` с `ensure_ascii=False`,
`sort_keys=True`, `separators=(",", ":")`. `model=None` обозначает отсутствие
сведений о модели исходного прогона. Сам manifest не доказывает происхождение
вручную упакованной базы, оператор должен использовать только снимок именно
синтетического запуска. Исходные JSON-метаданные не перезаписываются.

Новый результат хранит `resumed_from` с хешами базы и manifest, прежними попытками
и количеством контрольных точек. `retry_history` описывает новые сбои и задержки.
Сохраненная generation metadata стадий остается в базе и учитывается производственным
аудитом. Время нового процесса не равно суммарному времени исходного и возобновленного
прогонов. Для оценки нужно учитывать оба и сохранять одинаковые source-host/PDF
ограничения исходного и возобновленного запуска.

## Проверка источников

Для одинаковой пары запросов требуется одинаковый явный список публичных хостов:
повторяемый аргумент `--source-host имя.домена`. Поддомены и хосты перенаправлений
не разрешаются автоматически. Нельзя передавать URL, IP, Telegram или локальный
хост. DNS-ответ с непубличным адресом блокируется. Проверка публичного IP внутри
производственного reader сохраняется.

Это режим по умолчанию. Для полноценного сравнения поиска с производственным
поведением можно передать обеим версиям `--all-public-sources`. Тогда только
создание настоящего `PublicConnection` внутри source reader может добавить
конкретный публичный hostname в сетевой список этого процесса. Сам флаг не
разрешает HTTP-запросы к произвольным доменам. Неизвестные хосты вне reader остаются
запрещены. Telegram, локальные имена и буквальные IP запрещены также внутри reader.
Проверки HTTPS, credentials, порта, публичности всех DNS-адресов, перенаправлений
и лимиты чтения остаются производственными. PDF по-прежнему требует `--allow-pdf`.

Поле `dynamically_authorized_source_hosts` перечисляет хосты, которые запросил
reader. Это не доказательство успешного чтения: последующая проверка DNS или
получение страницы могут завершиться отказом. `source_exclusions` показывает
исключения стенда. Флаг и ограничения также сохраняются в новых recovery manifests
как `source_policy`. Для вручную упакованных старых снимков эту историю можно
передать дополнительным аргументом helper `source_policy`, отсутствие сведений
обозначается null.

Обнаруженный прежний список из 20 хостов исключал большинство доменов найденных
baseline-карточек. Такое сравнение отражает ограничение стенда и не принимается
как полная проверка поиска. Следующую пару нужно запускать в одинаковом
`--all-public-sources --allow-pdf` режиме. При возобновлении из старых контрольных
точек изменение условий чтения следует явно указать в отчете. Старые оценки
полноты источников не переносятся на новый прогон.

Без `--allow-pdf` стенд допускает HTML и текст, а PDF исключает. Это ограниченная
проверка доступности источников, ее нельзя считать полной проверкой первоисточников.
С `--allow-pdf` разрешена только точная команда существующего производственного
декодера. Сохраняются seccomp, Landlock, лимиты памяти, CPU и объема. На каждый запуск
проверяются путь и хеш reader, PDF до 8 МиБ, закрытое окружение, таймаут 32 секунды
и приватный выходной файл внутри временной базы. Прямой `Popen` остается запрещен.

Для содержательной приемки проверить `storage_audit.pdf_subprocesses`,
`source_exclusions`, фактически проверенные источники и ответ. Успех HTTP-запроса,
запуск декодера или средний балл сами по себе не доказывают точность цитирования.
Если разрешенный список исключил нужные первоисточники, пару следует оценивать как
сценарий недоступности, а полное сравнение авторов повторить с подходящими источниками.

## Слепая оценка

`review/answer-<случайный код>.txt` содержит задание, учебный материал и ответ.
Оценщику передаются только файлы из `review` в перемешанном порядке.
`keys/answer-<код>.json` хранит соответствие версии, хеши модулей и метаданные.
В выводе CLI нет полного ответа или названия версии. Файлы создаются с правами 0600
без перезаписи существующих файлов и без перехода по символическим ссылкам.

Отдельно оценить выполнение задания, точность, глубину, связность, язык и границы
интерпретации. Придуманная цитата и частичный ответ, представленный полным,
блокируют приемку. Сначала фиксируются оценки, затем раскрывается файл соответствий.
Одна пара не устраняет случайные различия модели и изменение доступности сайтов.

## Границы проверки

Поле `status=generated` означает получение текста. Оно не означает приемку.
`generation_complete` отражает только аудит завершения API, при отсутствии такого
аудита равно null. `legacy_pipeline_complete` сохраняет старый составной флаг
конвейера. Для двух запусков старой версии стенда поле `generation_complete`
имело смысл этого составного флага, их нельзя интерпретировать как аудит API.

Стенд проверяет композицию текста и временные контрольные точки. Он не проверяет
доставку, повторную доставку, привязку ответа к сообщению и финальную очистку очереди.
Эти проверки выполняются отдельно. Отсутствие сохраненного статуса короткого ответа
в composition-only запуске не доказывает ошибку Telegram-маршрута.

При импорте настоящего транспортного helper подавляются только четыре операции
обслуживания entry point: восстановление checkout, подготовка обновления,
восстановление dependency environment и его повторная активация. Уже выбранные
зависимости подключаются для чтения. Happy Eyeballs, OAuth, API и модель остаются
реальными. Число подавленных вызовов сохраняется в `bootstrap.suppressed_calls`.
Завершение внешним `timeout` без ответа является незавершенным прогоном.

Локальные guard-тесты не обращаются к модели, сети или нативному PDF-декодеру:

```sh
python3 -m unittest discover -s tests/isolated -p 'test_*guards.py' -v
```

Они проверяют в том числе соответствие реального вызова `passages` узкому
разрешению subprocess. Работу Linux sandbox и извлечение реального PDF нужно
подтвердить отдельным запуском на сервере.
