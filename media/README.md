# Загрузка и расшифровка записей

Веб-сервер принимает файл в Telegram Mini App частями. Отправитель видит выбранный чат до загрузки. При обрыве клиент запрашивает у сервера сохраненное смещение. Перед постановкой в очередь сервер сверяет полный файл. SQLite хранит задания и назначения. Страница истории доступна отправителю в контексте выбранного чата.

## Состав установки

- Сохраните рабочие модули Python из этого каталога и каталог `static/` в `/opt/psy-upload/`. Для HTML, CSS и JavaScript сборка не требуется.
- `server.py` принимает запросы и общается с `access_broker.py` через Unix-сокет. Брокер проверяет подпись Telegram и членство в заданной группе. Только брокер и процесс доставки получают файл `telegram` через systemd LoadCredential.
- `worker.py` получает задачу из очереди, запрашивает локальное распознавание через `asr_client.py`, повторно проверяет право доставки и отправляет результат. При подтверждении Telegram сохраняется message_id. Исход неопределенной отправки отражается в истории.
- `asr_service.py` принимает только соединения от системного пользователя доставки. `asr_sandbox.py` запускает `transcribe.py` с Landlock. Для каждой задачи процесс получает исходный файл, собственный каталог, установленные программы и локальную модель. Служба ASR использует отдельное сетевое пространство и отдельный UID. Декодеру нужны Linux с Landlock ABI >= 3, FFmpeg и ffprobe. Исходная установка использует Ubuntu x86_64 и Python 3.12.3.
- Для личного шлюза установите `audio-transcription-SKILL.md` как `$HERMES_HOME/skills/media/audio-transcription/SKILL.md` и `transcribe.py` как `scripts/transcribe.py` внутри этого навыка. Процесс личного шлюза должен иметь возможность читать модель. `telegram_handoff.py` подключается в адаптере Hermes под именем `plugins/platforms/telegram/psy_upload_handoff.py`. Для адаптера нужна библиотека python-telegram-bot из среды Hermes.
- `queue_health.py` читает сводные счетчики и числовой прогресс в пространстве монтирования сервера. В корневой инструкции описаны создание системных учетных записей, установка юнитов, ACL, путей и TLS.

Создайте 2 отдельные среды и установите зависимости из соответствующих файлов. Эти команды предполагают, что текущий каталог содержит исходники из `media/`.

```sh
python3.12 -m venv /opt/psy-upload-venv
/opt/psy-upload-venv/bin/python -m pip install -r requirements.lock.txt
python3.12 -m venv /opt/psy-asr-venv
/opt/psy-asr-venv/bin/python -m pip install -r asr-requirements.lock.txt
```

## Модель

Распознаватель использует многоязычную Systran/faster-whisper-base. Ревизия ниже и все 4 контрольные суммы в `model.sha256` сверены с установленной моделью. Команды скачивают публичные файлы. Для офлайн-развертывания перенесите проверенный каталог модели и пакеты Python через доступное хранилище.

```sh
revision=ebe41f70d5b6dfa9166e2c581c45c9c0cfc57b66
model=/opt/psy-asr-model
install -d -m 0755 "$model"
for name in config.json model.bin tokenizer.json vocabulary.txt
do
    curl --fail --location --show-error --silent "https://huggingface.co/Systran/faster-whisper-base/resolve/$revision/$name" --output "$model/$name" || exit 1
done
manifest="$PWD/model.sha256"
(cd "$model" && sha256sum --check "$manifest")
```

## Настройка доступа

Один экземпляр привязан к значениям `PSY_OWNER_ID`, `PSY_GROUP_ID`, `PSY_BOT_ID`, `PSY_BOT_USERNAME` и `PSY_PUBLIC_URL`. Задайте username без @. Укажите в публичном URL HTTPS origin без пути, параметров и пользовательских данных. Порт прямого TLS-листенера задает `PSY_LISTEN_PORT`, по умолчанию 9443. Адрес привязки задает `PSY_LISTEN_HOST`, по умолчанию 0.0.0.0. При прямом доступе порт входит в публичный URL, если он отличается от 443. Веб-сервер загружает опубликованную пару fullchain.pem и privkey.pem из `/etc/psy-upload/tls/current/`.

`PSY_ACCESS_SOCKET` указывает Unix-сокет проверки входа. В рабочих службах `PSY_UPLOAD_ROOT` и `PSY_UPLOAD_FILES` задают приватные точки монтирования очереди и исходников. `PSY_ASR_PROGRESS` указывает каталог числового прогресса. Для ASR нужны `PSY_ASR_INPUT`, `PSY_ASR_OUTPUT`, `PSY_WHISPER_MODEL` и `PSY_ASR_STANDALONE=1`. Личный шлюз использует обычный режим с проверкой путей Hermes. Для лимита исходников и результатов одного участника установите `PSY_MEMBER_QUOTA_BYTES`. Значение по умолчанию составляет 4 ГиБ.

Групповая точка входа использует `https://t.me/<имя_бота>?startapp=psy_group`. Для такого запуска у бота должно быть задано Main Mini App с вашим публичным HTTPS URL. Секрет бота в systemd credential должен соответствовать настроенному ID бота. Для надежной проверки членства через getChatMember нужны права администратора бота в заданной группе.

## Проверка кода

```sh
/opt/psy-upload-venv/bin/python tests/run.py
```

Проверка требует Node.js 22 или новее, Python 3.12 и поддержки Unix-сокетов. Она генерирует содержимое, временные аккаунты и SQLite, запускает настоящий HTTP API на loopback и проверяет возобновление передачи после обрывов. Распознавание в модульных тестах использует имитацию результата. Для отдельной проверки Linux-декодера с реальными весами выполните под непривилегированным пользователем на подготовленном сервере.

```sh
/opt/psy-asr-venv/bin/python tests/offline_smoke.py
```

Тест создает короткий синтетический WAV с тишиной, запускает тот же процесс Landlock и проверяет длительность, признак отсутствия речи и TXT. Оба набора проверок используют временные каталоги. Они не отправляют сообщения в Telegram.

## Восстановление расшифровок

Сохраняйте в одной закрытой резервной копии каталог подтвержденных результатов
`/var/lib/psy-recording-receipts`, ключ подписи recording-signing из системного
хранилища, базу очереди Mini App, исходные записи и контрольные точки ASR.
Для согласованной копии остановите прием новых заданий и дождитесь завершения
отправок, затем используйте резервное копирование SQLite или снимок файловой
системы. После восстановления проверьте владельцев, права и номера подтвержденных
доставок. Код на GitHub содержит только схему этих хранилищ. Приватные файлы и
ключ хранятся у владельца сервера. Старые задания без подтверждения источника и
назначения требуют новой загрузки через авторизованную кнопку.
